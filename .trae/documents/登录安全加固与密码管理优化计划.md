我将分两部分来完成您的需求：一是实现基于 Token 的安全验证机制，二是完善密码修改后的持久化与强制重新登录流程。

### 1. 登录安全优化：Token 验证

目前系统仅依靠本地存储用户名来维持登录状态，存在安全隐患。我们将引入 JWT (JSON Web Token) 机制。

**后端改造 (Electron Main)**:

- 安装 `jsonwebtoken` 库。
- 在 `electron/main.js` 中引入 JWT，并定义密钥。
- 改造 `auth:login` 接口：登录成功后生成 Token 并返回给前端。
- 创建安全拦截器 `handleSecured`：用于包裹需要鉴权的 IPC 接口（如设备增删改）。它会从参数中提取 Token 进行验证，验证失败则拦截请求。

**前端改造**:

- 修改 `src/services/ipc.ts`：在发起 IPC 请求时，自动从 `localStorage` 获取 Token，并将其追加到请求参数中发送给后端。
- 修改 `src/pages/Login/index.tsx`：登录成功后，将后端返回的 Token 存储到 `localStorage`。

### 2. 账户密码管理优化

确保修改密码后立即生效，并强制用户重新登录，同时保证数据持久化到磁盘。

**后端优化 (Electron Main)**:

- 增强 `auth:changePassword` 接口：
  - 增加错误捕获机制 (try-catch)。
  - 确保在修改密码后显式调用 `saveDatabase()` 将数据立即写入 `database.sqlite` 文件，防止重启后数据丢失。

**前端优化 (Profile Page)**:

- 修改 `src/pages/Profile/index.tsx`：
  - 密码修改成功后，除了清除 `loginUser`，同时清除 `token`。
  - 使用 Umi 的 `history` 对象强制跳转回登录页 (`/login`)，确保用户必须使用新密码重新获取 Token。

### 执行步骤

1.  **安装依赖**: 在项目根目录安装 `jsonwebtoken`。
2.  **后端实现**: 修改 `electron/main.js`，添加 Token 生成与验证逻辑，并应用到敏感接口。
3.  **前端通信层**: 修改 `src/services/ipc.ts`，实现 Token 的自动携带。
4.  **前端页面**: 更新登录页和修改密码页的逻辑，处理 Token 存储与清理，以及页面跳转。
5.  **验证**:
    - 测试登录是否生成 Token。
    - 测试无 Token 是否无法操作敏感接口。
    - 测试修改密码后是否强制登出，且重启软件后旧密码失效、新密码可用。
